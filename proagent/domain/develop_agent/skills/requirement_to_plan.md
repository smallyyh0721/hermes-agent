# Requirement To Plan

## When to use
- A user provides a PRD, phase milestone, bug report, or explicit feature ask.

## Procedure
1. Identify the requirement source and acceptance criteria.
2. Update the phase document if the implementation changes scope or behavior.
3. Break work into code, tests, docs, and deployment impacts.
4. Create or update a work item with status and test status.

## Output
Implementation plan with changed files, test plan, and handoff criteria.
